# T2.1 — Reducer v40 → v128: implementation plan

> Produced by a Plan agent 2026-09-27; reviewed by plan-verifier before execution (see bead T2.1).
> Status: **APPROVED WITH CHANGES** by plan-verifier (2026-09-27). The *Revisions* section below is binding and overrides the body where they conflict.

**T2.1 plan: Kotlin reducer v40 → v128, proven by `ReducerConformanceTest`**

**1. Decision: option (b), a persistent JSON-tree state with typed read-only views.** A compatibility shim keeps the current UI compiling.

Evidence from `events.mjs`:
- **Absent and null are different things all over the fold.** There are about 60 conditional-key sites (for example 1955, 1994-2033, 2146, 2187, 2489, 2504). Some writes set a key to `undefined`, which removes it. For example `tool_end` 2485-2486 sets `output: event.output, isError: event.isError`.
- **Existing objects are spread forward, so unknown keys survive:** 2167, 2235, 2375, 2422, 1416.
- **Event payloads are copied in verbatim:** `attachments` 2151, tool `input`/`output`, `warnings.raw`, `media`, `response` 2557.
- **Older snapshots may lack fields**, so the JS reads them with a fallback (for example `state.dismissedNotices ?? []`).
- **The typed model has already drifted.** `Projection.kt` says "absent key in JS maps to null here", `AttachmentMeta` keeps only 2 keys, `PROVIDER_IDS` includes `gemini` where the JS has only claude/codex/opencode, and `AgentEvent.ts` accepts only non-negative Longs while JS `eventTs` (1227) accepts any finite number.

Option (a) would need about 40 data classes, each with presence flags, plus a hand-written serializer. That doubles the code that can drift, and the serializer could itself hide a divergence. Option (c) as a live-decoded model costs O(transcript) per delta.

With (b):
- **Values:** `JsValue`, where Kotlin `null` means undefined. The types are `JsObj` (ordered `PersistentMap`), `JsArr` (`PersistentList`), `JsStr`, `JsNum(Double)` (same number semantics as JS), `JsBool` and `JsNull`. `put(k, null)` removes the key.
- **Performance:** a delta rebuilds only the path root → turn → block in O(log n), so a 5k-block transcript is never copied. Unchanged subtrees keep their identity, which lets Compose skip them. Appending message text is O(len) per delta, the same as JS; a rope is a later T14.1 option.
- **Debugging:** the state is the canonical tree, so a divergence is reported directly as a JSON path.
- **Cost:** the port code is stringly typed, as the JS is. The corpus catches key typos. This adds one dependency, `kotlinx-collections-immutable`, to `gradle/libs.versions.toml`, exposed from `:core:protocol`.

**UI blast radius.** 19 files outside `:core:reducer` import the model, including `ChatScreen`, `Composer`, `SubagentRuns`, `FakeTetherClient` and `Previews`. They keep compiling on the legacy `SessionProjection` through a shim that decodes per turn and per block, memoized by object identity. Screens move to the views in their own T5/T6 tasks.

**2. Work units.** The new code goes in `core/reducer/src/main/java/com/tether/app/protocol/fold/`. The v40 `reduce/Reducer.kt` and `reduce/Normalize.kt` stay untouched and live until unit D, so the app keeps working mid-port.

- **Parallel-work rule:** family executors never edit H0 or H1 files. A missing shared helper goes to the main session, or gets a private copy.
- **Code convention:** every ported function carries a `// events.mjs:NNNN` reference.
- **Per-unit gate:** the test takes `-Pparity.only=<glob>` so each unit can run just its own cases.

**Harness spec (H0).**
- **Integrity:** check every file's sha256 against `corpus-manifest.json`, and fail if `protocolVersion` is not 128.
- **Per case (JUnit4 `Parameterized`, one test per case):**
  - Feed `inputEvents` exactly as stored. Never re-stamp them.
  - Skip `null` sampling entries, but still fold every event.
  - Compare trees numerically (manifest rule) rather than as strings.
  - Stop the case at its first failing step.
- **Diff report:** case name and source kind, step index, the compact input event, then up to 10 divergences. Each gives the JSON path (for example `$.turnsById["t1"].blocksById["b2"].text`), a label (`missing` / `extra` / `null-vs-absent` / `type` / `value`), and truncated expected and actual values.
- **Run summary:** a histogram of failing paths normalized to `turnsById.*.blocksById.*.ts`, which shows which unit owns a failure.
- **Serializer self-test:** parse every corpus file, write it canonically, and require byte equality. Numbers need an ECMAScript `Number::toString` formatter; use JDK 19+ shortest-repr `Double.toString` and rewrite the exponent.

**3. Corpus handling.**
- **Fixture vs synthetic cases:** fixture cases are already the adapters' `AgentEvent` output, so no adapter (`claudeToEvents` and so on) is ported. Both kinds run through the same harness. Fixtures are the integration gate; synthetic cases map to units.
- **`seq`/`ts` stamping:** the stamps (ts = 1790000000000 + seq×1000) are already inside `inputEvents`. Unstamped events must stay unstamped: `syncTurnRun` 1503 and `blockEventTs` take no-op paths on them. The fold reads `ts` raw from the event tree with the helper each JS call site uses (`eventTs` vs `nonNegativeFiniteNumber`), never through `AgentEvent.ts`.
- **Time:** the reducer never reads a clock. `events.mjs` line 4 says it is pure, and a grep finds no `Date.now`. `nowMs` exists only in helper cases, which belong to T2.2. Add a test that fails if `fold/` references `System.currentTimeMillis`, `Clock` or `Instant.now`.
- **Code shared with T2.2:** the `CanonicalJson` codec in testFixtures (T2.2 adds the `$undefined`/`$map`/`$number` typed-value layer on top), plus `Js.kt` for code-point bounding and `jsTrim`. The helper corpora `model-id.json` and `conversation-story-points.json` read the same projection shape.

**4. Risks and mitigations.**
- **JS/Kotlin semantic mismatches** (`??` vs `||`, truthiness, UTF-16 `.length` vs `Array.from` code points, trim, `Number.isInteger`): the `Js.kt` helpers get their own unit tests, and ports go line by line with line references.
- **Key order in `JSON.stringify` at 895 (`coerceTaskResultText`):** it uses insertion order, but the corpus stores events with sorted keys. If todo-* fails on this, it is an S0.2 generator question (did the exporter fold events decoded from the stored file?), not a Kotlin bug.
- **Corpus drift:** the sha and version checks, and re-vendoring through `tools/parity/sync-corpus.sh`.
- **Performance:** persistent maps. If the stress test regresses, swap the storage inside `JsObj` (its API hides it).
- **Legacy shim shows only the v40 subset:** acceptable. It is explicit and temporary until the screens migrate.

**QuickJS fallback trigger (needs owner sign-off; record as a blocked 👤 gate in beads):**
- after A–C and I, cases are still red on semantics that cannot reasonably be matched; or
- the corpus shows repeated drift: a `syncParityCorpus` refresh breaks more than about 10% of steps two refreshes running; or
- the port stays more than one tether protocol version behind.

If it triggers, only `reduce()` moves behind a Kotlin interface. The tree and views stay, so the UI is unaffected.

## Revisions (binding — plan-verifier APPROVE-WITH-CHANGES, decisions by claude-main 2026-09-27)

1. **Unit I is enumerated, not counted.** `parity-corpus/reducer/` has **16** `fixture-*` cases, not 19. Unit I = the 16 fixture cases + `provider-projection-limits`, `codex-app-server-representative`, `opencode-provider-session` = **19 named cases**; H0 writes the list into `conformance/units.txt` (case → unit) and a test asserts every corpus case appears in exactly one unit.
2. **Disjoint line ownership.** H1 owns 557–634 (incl. `sameStringList` 557–561 and the shared normalizers 587–634); **B starts at 635**; **C's CLI helpers are 562–586**. H0 adds a check (script or test over `units.txt` ranges) that every events.mjs line 215–1607 falls in exactly one unit's range.
3. **Single acceptance owner for shared cases.** `cancel-interrupted` → owned by **A** (runs after B lands); `plan-diff-reroute-review-compaction` → owned by **C** (runs after B lands). The non-owner only fixes its own family file.
4. **Number formatting = a shortest-repr port in `Js.kt` (main code).** The reducer needs ECMAScript `Number::toString` at **runtime** (`JSON.stringify` at 895), and neither JDK 17 nor ART guarantees shortest output. H1 ports Schubfach (or Ryu) into `Js.kt` (pure Kotlin, KMP-friendly), used by both the runtime stringify and the canonical test writer. Unit tests: `5e-324`, `1e21`, `1e-7`, `0.1+0.2`, `2^53+2`, `-0`, `123e-20`, `1.7976931348623157e308`, integers ≤ 2^53.
5. **`JSON.stringify` key order.** `Js.kt` implements JS order: integer-like keys first ascending, then other keys in insertion order. `JsObj` preserves insertion order. H1 checks the todo cases' stringified content now and records the result in `units.txt`'s header; if the corpus's sorted storage conflicts with insertion order at 895, file it against S0.2 (exporter) before porting C.
6. **Identity rule is asserted.** Harness: whenever step N's expected projection equals step N−1's, Kotlin `reduce` must return the **same object** (`===`). (JS relies on this at 1692, 2063, 2087, 2308, 2624; it's what lets Compose skip.)
7. **Compose stability (unit D).** Add a Compose `stabilityConfigurationFiles` entry for `com.tether.app.protocol.tree.*` in the UI modules (no `@Immutable`/Compose dependency in core). `JsObj`/`JsArr.equals` check identity first.
8. **Unit D is its own bead `T2.1D`** — depends on T2.1 **VERIFIED** and T1.1 **merged**. T2.1 DONE = 70/70 corpus cases green + the checks above; D is not part of it.
9. **Legacy adapter is proven before deletion (D).** Before deleting v40 `Reducer.kt`/`Normalize.kt` and their tests, a test runs the old v40 Golden/Lifecycle inputs through new reducer + adapter and compares the `SessionProjection`. Delete only after it passes. H0–I is purely additive; rollback of D = one revert.
10. **Mechanical event-type coverage.** A test extracts every `case "…"` label from `reduceEvent` (events.mjs 1609–2900, via the vendored events.mjs copy H0 adds under `parity-corpus/reference/events.mjs` with its sha) and asserts the Kotlin `when` handles each explicitly.

Optional (adopted): D's stress test records memory per block and a hard perf bar for T14.1 (**p99 per `message_delta` < 2 ms at 5k blocks** on the JVM); the purity guard test also forbids `SystemClock`, `Random`, `Instant.now`, `Clock`, `System.currentTimeMillis` in `fold/`; QuickJS-fallback trigger #1 becomes "any case still red 3 days after unit I starts, with the path histogram attached to a 👤 blocked bead".
