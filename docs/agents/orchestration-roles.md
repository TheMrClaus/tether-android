# Roster and routing — fleet policy

Read before the first dispatch; lanes read their role and applicable routing rules.
Installed by game-orchestration; model pins and permissions remain binding.

## Roster

| Role | Who (pinned in `.claude/agents/`) | Does | Never |
|---|---|---|---|
| **Lead / main orchestrator** | **Opus 5.5 (1M)**, xhigh — the session itself (Tether: set the session's Effort row to xhigh; a lead that finds itself below xhigh says so in its first report) | Plans waves, writes briefs, spawns agents, verifies their work, runs builds/tests/the dev server, captures screens, gates, integrates and pushes, deploys, owns the tracker's STATUS/DONE; may call the **image lane** directly for a single asset and route the result to `design-director` | Implements features; makes design calls (rule 3 has the one exception) |
| **Design: all of it** | `design` (**Opus 5.5 (1M)**, xhigh) | Every piece of design: UI/UX structure and flow, layout and spacing, type scale, colour and tokens, component and screen design, empty/loading/error states, interaction and motion specs, iconography — plus the design spec a piece is judged against. **Every raster asset it needs is generated by the Codex image lane it drives** | Anything that isn't design; grading its own design; product code beyond a design's own spec/tokens/styles; shipping design no one judged |
| **Design director** | `design-director` (**Opus 5.5 (1M)**, high, read-only) | The run's design judge: **APPROVE/REJECT against one reference** (the bar screen, mock or concept the run doc names); a REJECT names **every BLOCKING finding, ranked** — bar line, evidence, smallest change (gauntlet-core › Findings) | Executing, editing, building; being the first opinion where the blind critics exist |
| **Image assets — icons, buttons, illustrations, textures, reference images** | **The Codex image lane (`astra`, High)** — `codex exec -m gpt-6-astra -c model_reasoning_effort=high` running the built-in `imagegen` skill (gpt-image-2 on the subscription, no API key) — **driven by the `design` lane**; the lead may call it directly for a single asset | Every raster asset a design needs: app and UI icons, buttons and controls, illustrations, textures, backgrounds, empty-state art, marketing and social images, and the **reference images** a design brief needs before the design exists | Judging; anything outside the design lane's brief; 3D of any kind; committing an asset without its recipe |
| **Complex coding** | `builder` (**Sonnet 5.5**, medium) | App and API logic, data model and migrations, auth, integrations, build and tooling, the hard refactors | Deploying; grading its own UI; merging |
| **Light coding** | `scout` (**Sonnet 5.5**, medium) | Wiring, config, docs, copy, data entry, recon reported as `file:line` | Redesigns; anything architectural (hands the seam back to `builder`) |
| **The lead's critic** | `wave-check` (**Opus 5.5 (1M)**, medium, read-only for code) | Reviews every wave plan **before** any brief goes out | Proposing or designing work |
| Blind critics / ground-truth audit | workflow agents (inherit the lead: Opus 5.5) | Blind replicas per screen against its bar, plus one naive reader per capture | — |

**Never assign work to a retired role name or model.** In this fleet there is no `artist`, no
`astra` **role** (the Codex image lane is a child the `design` lane runs, not a peer agent), no
Fable and no Sonnet 5, and **no 3D pipeline at all**: Meshy, Blender, Unity, rigs, meshes and
textures-for-3D are out of scope for apps — if a task genuinely needs 3D, it belongs to the Games
fleet. The roster table above and `.claude/agents/` frontmatter are the pins; no brief, tracker or
prompt may name a retired role or model.

## Routing rules

1. **Spawn the repo roster by name with no model/effort override.** The global
   `native-orchestration` skill explicitly exempts repo-local rosters from its override rule.
2. **All design work goes to `design`; all image *generation* goes to the Codex image lane.** The
   lane has exactly one job: raster assets — icons, buttons, illustrations, textures, reference
   images. It runs the pinned command `codex exec -m gpt-6-astra -c model_reasoning_effort=high`
   with the built-in `imagegen` skill, **driven by the `design` lane**; the lead may call it
   directly for a single asset and then route the result to `design-director`. No leaf outside the
   design lane runs imagegen. Every generated asset is committed **with its recipe** (the exact
   prompt, the command, the output path), so it can be regenerated or re-commissioned.
   - **One image lane at a time.** The lane spends the owner's subscription quota: no speculative
     batches, no asset the brief did not ask for — ask `design` first whether an existing asset or
     a code-drawn icon (inline SVG, an icon font, a CSS/`currentColor` shape) does the job cheaper.
     A raster asset is for what vector/CSS genuinely cannot do.
   - **Never re-inline a raw generated image into a transcript.** The built-in tool writes to
     `~/.codex/generated_images/<threadId>/` — copy the file out to the lane's paths and reference
     it by path. A multi-MB base64 payload in a codex transcript hits the 16 MiB frame cap and
     makes the session un-resumable.
3. **The lead never implements in a run.** If a run's lead is about to edit code or design, it
   spawns an agent instead. The lead keeps the build/test gates, the shared dev instance, screen
   captures, integration and pushes, deploys, tracker STATUS/DONE, and the lifecycle of any
   long-running process it starts. **Interactive exception:** in a session that is *not* a run, the
   session may make **one small edit itself** when all of these hold — one file, not design, not
   Core/business logic or schema, and no design verdict needed (a typo, a doc line, a config value,
   a one-line fix with its test). Anything bigger, or a second edit, goes to the roster. The edit is
   still verified by someone other than its author when it changes behaviour.
4. **Verdicts come from instruments, not the maker.** A design is judged against **one** reference
   by the blind critics, with `design-director` ruling where they disagree; until the critic
   workflows exist, `design-director` judges alone — and the report says so. A UI claim is verified
   with a **screen capture from a real browser at the run doc's viewports** (desktop and phone),
   never with prose; the run's own gates (tests, typecheck, lint, build) are read from their real
   output line. **Independence is by context, not by model**: maker and director share a model's
   blind spots — reports say "blind, fresh-context", never "independent model", and a verdict that
   rests on taste rather than a reference or a measured number is labelled as such.
5. **Hand-offs:** `scout` → `builder` when a task turns out to be architectural; `design` → the lead
   for a better reference or a re-commission when a piece cannot reach its bar; `builder`/`design`
   → the lead for anything needing a deploy.
6. **Prove runtime identity on the first real dispatch and at wave boundaries.** Record the
   lead and each role's actual provider/model/effort from startup telemetry or native transcript
   metadata; labels/requested models alone are not proof. Use the fleet's `models` helper where
   supported, otherwise record the native evidence and applicable roster/owner-selected model.
   Check identity before expensive work. A separate no-op probe is needed only when the harness
   cannot expose it otherwise, once per runtime configuration change, not per handover. Missing
   telemetry is UNKNOWN; wait for its event rather than sleep-polling. A confirmed mismatch stops
   the affected lane for the owner; never silently substitute a model.
7. **HARD RULE: every Opus agent is Opus 5.5 (`claude-opus-5-5[1m]`), never Opus 5.** Applies to
   pins, spawns and workflow `agent()` calls alike. Do not use the global `~/.claude/agents` for a
   run: this repo's roster is the reviewed policy.
8. **Every agent logs its own work** in this repo's tracker/write protocol (beads — see Tracking) —
   as a **one-line row**: state, verdict, and the path to the body. The body goes in your own file;
   never paste it into the tracker (run-core › *the tracker is an index*). The lead owns STATUS and DONE. `wave-check` and `design-director` are read-only apart from their
   own verdict and log rows — **enforced** for file edits by the fleet gate (inside a checkout they
   can write Markdown only); their Bash stays open for inspection, and there the rule is still their
   word.
